二、实现过程（第二层任务 1：新增系统调用）  
1.实验目标  
在 xv6 中新增自定义系统调用getpid_plus()，实现返回当前进程 PID+1 的功能，并通过用户程序验证。  
2.核心实现步骤  
定义系统调用号：在syscall.h新增#define SYS_getpid_plus 22  
注册系统调用：在syscall.c添加函数声明与分发数组映射  
实现内核逻辑：在proc.c编写sys_getpid_plus()，获取当前进程PID并加1返回  
添加用户接口：在usys.S和user.h完成用户态调用支持  
编写测试程序：新建test_getpid_plus.c调用新系统调用并打印结果  
编译配置：在Makefile的UPROGS中添加测试程序

三、问题及解决方法  
1.用户态/内核态打印函数混用报错原因：用户态用cprintf、内核态用printf，函数不兼容  
解决方法：用户态固定用printf，内核态固定用cprintf  
2.echo命令输出调试信息时，字符拆分、刷屏混乱
解决方法：将用户态逐字打印的printf替换为write系统调用，一次性输出完整字符串，仅触发一次系统调用，保证输出整洁完整
3.QEMU 启动报错 “端口被占用”，疑似是上一次运行的xv6未正常退出，VNC端口残留占用  
解决方法：执行docker stop xv6-reading停止容器，然后docker start xv6-reading重启容器  
4.第一层打印刷屏，无法查看第二层结果  
解决方法：注释掉第一层所有调试打印语句
